# askeden.com Worker: bug and break sweep, 2026-10-08

Scope: `site/src/worker.js`, `src/eden/*`, `src/accounts/*`, `src/browser/*`. Method: close reading of the risky paths,
the unit tests (431 pass after this sweep, 5 of them new in `site/test/sweep-20261008.test.js`), and about 120
unauthenticated requests against https://askeden.com and https://preview.askeden.com (no sign-in, no account created,
no payments, e-mail or calendar calls, no load). Nothing deployed.

Severity: High / Medium / Low / Info. Status: FIXED (in this commit), OPEN (documented, not changed).

## Checklist

1. http to https redirect incl. POST: **TESTED-OK.** `POST http://askeden.com/api/web/signout`, `/signin?a=1&b=2`, `www.` and `preview.` all answer 308 to https with path and query kept (so a POST stays a POST). Localhost excepted by design. Unit tested already.
2. Unauthenticated `/api/*` routes: **TESTED-OK.** Every route in worker.js, index.js, session.js, chat.js was probed with GET, POST and OPTIONS (about 60 routes). Session or token routes answer 401, chat routes 403 (no `X-Jarvis-Chat`) then 401, unknown 404, wrong method 404/405. Deliberately open and cheap: `/api/web/config`, `/api/web/link` (rate limited), `/api/voice` (needs a 32-hex install id), `/api/stripe/webhook` (signature), `/api/web/passkey/*` (Origin, Turnstile for signup). **FOUND-BUG** on the way: see B1 (a broken %-escape gave 500 instead of 4xx).
3. Origin and CORS (`fromElsewhere`): **TESTED-OK.** Evil, `null`, look-alike (`askeden.com.evil.com`) Origins on POST/DELETE are refused 403 on every `/api` route; OPTIONS is 403 everywhere except `/api/eden/*`, which echoes CORS only for `https://messenger.askeden.com` (and loopback dev origins when `EDEN_ASK_DEV_ORIGINS` is set). Apple's form_post callback accepts only Origin `appleid.apple.com` or `null`, and only that path. Stripe's webhook skips Origin by design.
4. Malformed input: **TESTED-OK + FOUND-BUG (B1).** Bad JSON, JSON `[]`/`null`, wrong content-type (415), 3 MB bodies (413 on passkey verify, Apple sign-in, Stripe webhook; 401 before body on Help), `//api/account`, `/api//account`, `%2e%2e`, `%00` (Cloudflare 400), trailing slashes, 9 KB paths, `/💩`, `%ff`, `\evil.com`, `/messenger//evil.com` (stays on messenger.askeden.com), CRLF in paths: no leaks, no stack traces, no open redirects. B1 found with `PUT /api/sync/%E0%A4%A`.
5. Stripe webhook: **TESTED-OK (live: unsigned 400 `bad_signature`, wrong method 405, 3 MB 413) + code review, with FOUND-BUG items O6 and O7.** Signature is HMAC-SHA256 over `t.payload`, constant-time, 5-minute tolerance both ways, several `v1`, raw body size capped at 1 MiB. Idempotency: per-account `stripe_seen` (event id, 30 days, last 100) and credits by purchase id. Order: older events never undo newer ones, a cancelled subscription never returns. Credits: FIFO by expiry, 12-month lots, never below zero. Auto top-up: `pending` written before the Stripe call, idempotency key `eden-topup-<account>-<n>` reused on retry, at most one try an hour, `payment_intent.succeeded` is deduplicated by PaymentIntent id. Legacy $20 price is honoured only if in `STRIPE_PRICE_PLUS_LEGACY` (it is, in wrangler.toml); yearly price is honoured and sold only if set (it is). Livemode events ignored unless `STRIPE_LIVE=1`.
6. Sign-in flows: **TESTED-OK (code review) with OPEN O1.** Apple (state in a `__Host-` SameSite=None cookie, nonce hashed, audience checked, form_post origin rule), Google (code + PKCE S256, state, nonce, `email_verified` required, RS256 keys from Google's JWKS, issuer/audience/azp/exp checks), passkeys (challenge stored server-side single-use for 5 minutes and bound to mode/RP ID/origin/native/browser; UV and UP required; rpIdHash, origin, `crossOrigin`, signature, counter checked; attestation `none` only). Identities are never matched by e-mail, so no takeover by e-mail; linking needs a signed-in session and the identity DO refuses a second owner (409). Turnstile: hostname of the verdict must equal the request host; token single use at Cloudflare. SIGNUPS fails closed without both Turnstile keys; OWNER_DOMAINS applies only to Google e-mails that passed `email_verified`. Session cookie: `__Host-eden`, Secure, HttpOnly, SameSite=Strict, Path=/. Live: signup passkey options without a Turnstile token 403; **but the native twin without Origin returns 200 (O1).**
7. Chat sync and saved memory: **TESTED-OK (code review + existing tests).** Everything is keyed by the session's account; ciphertext is bound to account and id (AAD), so a tampered or swapped id fails to open; ids `[A-Za-z0-9._:-]{1,120}`; 1.5 MB per chat, 5000 chats, 200 MB per account; deletes leave a tombstone; delegates and space members are refused (`grant_forbidden`). Memory: 200 items x 300 chars, compare-and-set on a version, owner only. Note O9 (tombstones never purged).
8. Browser agent and cloud browser: **TESTED-OK + FOUND-BUG (B2, B4, B5, B6).** Every request of every tab, redirects included, is intercepted (`Fetch.requestPaused`) and checked by `addressAllowed`: http(s) only, no credentials, private/loopback/link-local/CGNAT/multicast/reserved IPv4, IPv4 in decimal/hex/octal/short forms (the URL parser normalises them), IPv4-mapped and NAT64 IPv6, `.local/.internal/...` names, bare names. Gaps found and fixed: `fec0::/10` and 6to4 `2002::/16` addresses embedding a private IPv4 (B5). Residual: hostname-only filter, so a public name that resolves to a private address (DNS rebinding, `nip.io` style) passes (O13; the browser runs on Cloudflare's network, not yours). One BrowserSession object per account (`idFromName(account)`), reached only through the Worker after the session check; a delegate cannot drive or steer it (B6). Minutes: counted in the object (`usage`), checked at launch and on a 20-second tick; free 60 / Plus 600. Approvals for risky agent actions are held server-side in the object (`agentPending`, single use, 10 minutes, same page) and are only consumed through the Worker.
9. Refusal retry and chat identity: **TESTED-OK (code review + refusal.test.js).** Refusal classification is rule based after the reply; copyright and safety kinds are never retried; the retry is one ordinary new turn the client sends with `refusalRetry`, so no loop is possible without spending allowance. Identity and copyright rules ride in `EDEN_IDENTITY` for every model.
10. Video upload and code run: **TESTED-OK (code review) with OPEN O4; run endpoint SKIPPED live** (`CODE_SANDBOX` is not bound yet, it answers 503 "coming soon", so its minute metering cannot be exercised; the checks in `run.js` read correctly: 100 KB code, 64 KB stdin, 30 s, per-account rate). Video: 100 MB cap by Content-Length enforced with a FixedLengthStream, 20/60-minute caps by Gemini's own metadata with a delete on failure, file names restricted to `files/[a-z0-9-]{1,64}` and URIs to Google's host, files deleted in the turn's `finally`.
11. Gmail / Calendar proxy: **FOUND-BUG (design) O2.** Scopes are checked (Gmail needs readonly+compose, Calendar needs events), tokens are sealed per account (AES-GCM, HKDF key per account, AAD) and never returned to the browser or logged, delegates only through explicit grant features. But the approval for sending mail or writing the calendar exists only in the page: `POST /api/chat/gmail` with `action: "send"` and `POST /api/chat/gcal` writes run straight away for any signed-in same-origin request.
12. Error responses: **TESTED-OK.** All 5xx paths return `{"error":"Something went wrong on the server. Try again.","code":"server"}` and log the stack server-side only; 400/404 messages are fixed strings; no keys, URLs or stack traces seen in any probe. Provider error text (Google's message, 200 chars) is passed to the person who caused it.
13. Security headers and CSP per page type: **TESTED-OK.** `/`, `/signin`, `/privacy`, `/terms`, `/help`, `/help/`, `/download`, `/jarvis`, `/edu`, `/p/<id>`, `/eden/connect`: each has a CSP and X-Frame-Options DENY, HSTS, nosniff, referrer policy. Eden app, artifact (sandbox), runner (sandbox, no framing header: harmless) and landing CSPs read in `eden/web.js`; API answers are `no-store`. Notes O11 (HSTS without includeSubDomains/preload) and O14 (preview is an older build: `/edu` is a 302 there).
14. Rate limits: **TESTED-OK (code review), O8, O5.** Sign-in start/callback/passkey/handoff/native: AUTH_RATE (20/min/network), new accounts also `new:<ip>`, native new accounts cost 5 tries; link start/poll/lookup: LINK_RATE; chat/voice/API: API_RATE, EDEN_RATE, BROWSER_RATE, RUN_RATE; Help daily caps; delegate/space codes LINK_RATE per account. Live bursts were deliberately not run. Limitation: `limited()` returns silently when a binding is missing (fails open) and Cloudflare's limiter is per location.
15. Logging: **TESTED-OK.** Every `console.*` in `src` was read: no tokens, e-mails, keys or page content. Error paths log `error.message`/`stack` (a Gemini key travels in a header, never a URL). Info: cloud-browser launch errors may contain a URL (sliced to 200 chars).
16. Secrets in repo and `wrangler.toml` vars: **TESTED-OK.** `git grep` for Stripe/Google/Anthropic/GitHub keys and private keys finds only documentation. `[vars]` hold public identifiers only (Stripe price ids, Google client id, Turnstile site key, Apple team and Services ids). All secrets are `wrangler secret`.
17. Account deletion vs data stores: **FOUND-BUG B2 (fixed) and O3 (open).** See the table below.

### Open (not changed: auth, crypto, billing or larger than a small fix)

| ID | Sev | What | Repro / evidence | Suggested fix |
|---|---|---|---|---|
| O1 | Medium | Turnstile is bypassed by the "native" endpoints, which only require that there is no Origin header, so any script can use them. New accounts then cost only `NATIVE_NEW_WEIGHT` (about 4 a minute per network, unlimited across networks) and each gets the free trial allowance and 60 browser minutes. | `curl -X POST -H 'content-type: application/json' -d '{"mode":"signup"}' https://askeden.com/api/web/native/passkey/options` returns 200 with a challenge (no account was created; the register and verify steps follow the same path). The web twin returns 403 without a token. | Gate native signup on Apple App Attest / DeviceCheck or an app-signed token, or require Turnstile (or a proof of work) for native passkey signup; lower the per-network weight; cap trial grants per network. Matches the public-launch gate in memory. |
| O2 | Medium | Gmail send and Calendar create/update/delete have no server-side approval. Only the page asks. Any signed-in same-origin request (XSS in the app, a compromised extension acting through the page, a bug in the page) can send mail as the user. CSP `script-src 'self'` and the session being HttpOnly limit this; they do not remove it. | read `google-data.js` `POST /api/chat/gmail` and `/gcal`: `runGmailAction` runs on any `action`. | Issue a short-lived, single-use approval token from a user-gesture route bound to a hash of action+args; require it for `send`, `schedule`, `draft` with send, calendar writes, `deleteDraft`. |
| O3 | Medium | Account deletion does not touch Space DOs (owner's shared sealed chats, member rows with account ids, member public keys) or delegate/space rows on other accounts. Content is sealed with a space key the server never has, but membership metadata and blobs stay forever. | `eraseAccount` has no spaces step. | On delete: for owned spaces call a `space-erase`; for joined spaces call `leave`; and remove delegate records that name the account on the owners' side. |
| O4 | Medium (availability/cost) | Video uploads have only the 120/min API limit. A free account can push 100 MB files into the owner's Gemini Files project (20 GB project quota, 48 h retention) and never send a turn; orphans are never deleted by us. | read `videoApi`: deletion only in the turn's `finally`. | Per-account upload limit (e.g. 5 an hour, 500 MB a day), remember uploaded names per account and delete orphans on the next call or by alarm. |
| O5 | Low | `/api/voice` without an account: anyone can mint 32-hex install ids; per-network and global daily caps are the only guards, so a few networks can exhaust the 400k global characters and silence the voice for everyone for the day (and spend the owner's Fish Audio credit up to that cap). | by design; no probe sent | Require an app token for the hosted voice, or make the global cap per country/ASN as well. |
| O6 | Low-Medium | Stripe: `charge.refunded` and `charge.dispute.*` are ignored (`default: ignored type`). A refunded or charged-back credit pack keeps its credits; a refund does not end Plus unless the subscription is cancelled too. Credits are granted by `metadata.pack`, not checked against `amount_total`. | read `handle()` | Subscribe the endpoint to those events; claw back unspent lots; compare `amount_total` to the pack price. |
| O7 | Low (operational) | A Stripe subscription whose price id is not in `STRIPE_PRICE_PLUS`, `_LEGACY` or `_YEARLY` is silently ignored (200 `ignored`): the customer pays and gets no Plus. Currently all three are set. | read `plusPrice` / `takeSubscription` | Log a warning (price id only) when a subscription for a known account has no honoured price. |
| O8 | Low | Unauthenticated requests with a well-formed Bearer token and a random account UUID wake a new Account Durable Object each (`call()` goes to the DO before the secret is checked); no pre-auth limiter on `/api/account`, `/api/esync`, `/api/csync`, `/api/sync`, `/api/relay`. Cost and noise amplification. | `curl -H 'authorization: Bearer jv1.<random uuid>.<16 hex>.<43 chars>' https://askeden.com/api/account` (not run in volume) | IP-keyed limiter on 401 outcomes, or reject unknown accounts at the Worker with an `exists` cache. |
| O9 | Low | Chat-sync tombstones are never purged; `csync-list` loads every `cvm:` row. A user creating and deleting many ids slows only their own account. | read chat-sync.js | Purge tombstones older than 90 days after devices have caught up (or cap them). |
| O10 | Low | The handoff login-CSRF guard accepts requests with no `Sec-Fetch-Site` header (older browsers). The 43-char one-time code is unguessable, so this needs a leaked code. | read `handoff()` | none needed; note only. |
| O11 | Low | HSTS is `max-age=31536000` without `includeSubDomains` / `preload`; the apex serves `edu.askeden.com` and `messenger.askeden.com` redirects. | response headers | add `includeSubDomains` once every subdomain is https only. |
| O12 | Low | Sealed data (chats, memory, keys, Google tokens) uses one Worker secret `EDEN_TOKEN_KEY` with no version tag in the record; rotating or losing it makes everything unreadable. | read tokens.js | Add `kid`/version to sealed records and accept two keys during rotation; back the secret up offline. |
| O13 | Low | Cloud browser SSRF filter is by host name; a public name resolving to a private address passes (the browser runs on Cloudflare's network, so it cannot reach your LAN). | `addressAllowed('http://1.1.1.1.nip.io/')` ok | accept as is, or resolve via DoH before navigating. |
| O14 | Info | `preview.askeden.com` runs an older build than production (e.g. `/edu` returns 302 there, 200 on production). It shares the production Turnstile site key. | curl | redeploy preview before testing there. |
| O15 | Low | `limited()` silently allows everything when a rate-limit binding is absent, and the Cloudflare limiter is per location, not global. | read `accounts/index.js` | log once when a binding is missing; treat limits as soft. |
| O16 | Info | `POST /api/chat/run` parses the whole JSON body before the size check (signed-in only). | read run.js | check `content-length` first like `readBody`. |
